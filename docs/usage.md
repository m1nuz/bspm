## Build a folder

A folder of C++ sources can be built directly, without a configuration file:

```console
bspm build examples/nested-sources
bspm run examples/nested-sources
```

To create a new folder project:

```console
bspm init hello
bspm build hello
bspm run hello
```

Inside a project folder, bare `build`, `run`, and `clean` use the current
directory. In a configured project, they select its default target instead. See
[project configuration](projects.md) for target selection and `--project`.

## Choose a compiler and build mode

The default build uses GCC, debug flags, and one compilation job. Select a
compiler explicitly or enable release mode:

```console
bspm build hello -c g++
bspm build hello -c clang++
bspm build hello -c msvc
bspm build hello --debug
bspm build hello --release
```

Release mode enables optimization and defines `NDEBUG`. Check that the
selected compiler and its associated tools are available:

```console
bspm doctor
bspm doctor -c clang++
bspm doctor -c msvc
```

For parallel compilation, supply a positive job count:

```console
bspm build hello -j 4
bspm build hello --jobs 4
```

Independent source files compile concurrently. Importable module units are
compiled in dependency levels, allowing independent interfaces in the same
level to compile in parallel.

## Build executables and libraries

Use `-o` or `--output` to choose the output name. Executables are the default;
`--lib` and `--shared` select library targets:

```console
bspm build hello --bin -o hello
bspm build hello --output hello
bspm build examples/static-library --lib -o math
bspm build examples/shared-library --shared -o greeting
```

When the requested output name has no extension, `bspm` adds the appropriate
prefix and extension:

| Option | Windows | Unix-like systems |
| --- | --- | --- |
| `--bin -o hello` | `hello.exe` | `hello` |
| `--lib -o math` | `libmath.a` with GCC/Clang; `math.lib` with MSVC | `libmath.a` |
| `--shared -o greeting` | `greeting.dll` | `libgreeting.so` |

Outputs are placed under the target's profile-specific `build/` directory.
For projects that link an application to libraries, use
[target dependencies](projects.md#target-dependencies).

## Discover sources

`bspm` scans target directories recursively for `.cpp`, `.cc`, `.cxx`, `.c++`,
`.cppm`, `.ixx`, and `.mpp` files. A target can therefore use nested folders:

```text
hello/
├── src/
│   └── main.cpp
└── modules/
    └── hello.cppm
```

Generated directories such as `build/`, `.cache/`, and `gcm.cache/`, as well
as directories whose names start with `.`, are skipped during discovery.

Use `--source` to select files or directories, and `--exclude` to omit them.
Paths are relative to the target root; repeat the flags for multiple paths:

```console
bspm build hello --source src --source modules --exclude src/generated
```

## Use C++ modules

`bspm` discovers module declarations and imports, then orders compilation
according to their dependencies. Named modules can use primary interfaces,
implementation units, exported partitions, internal partitions, and local
partition imports.

The [module-partitions example](../examples/module-partitions) separates these
forms into individual files:

| File | Declaration or import |
| --- | --- |
| `math.cppm` | `export module math;` and `export import :ops;` |
| `ops.cppm` | `export module math:ops;` |
| `detail.cppm` | `module math:detail;` |
| `math.cpp` | `module math;` and `import :detail;` |
| `main.cpp` | `import math;` |

```console
bspm build examples/module-partitions
bspm run examples/module-partitions
```

The [header-unit](../examples/header-unit) and
[std-module](../examples/std-module) examples demonstrate `import <print>;`
and `import std;`. Their availability depends on compiler and standard-library
support. The source generated by `bspm init` also uses `import <print>;`.

## Customize compilation

Add include directories, preprocessor definitions, compiler flags, or linker
flags. Repeat an option for each value:

```console
bspm build hello --include include --define APP_DEBUG=1
bspm build hello --cxxflag -Wall --cxxflag -Wextra
bspm build hello --include "third party/include"
```

For example, with GCC or Clang on a platform using `-pthread`:

```console
bspm build hello --cxxflag -pthread --ldflag -pthread
```

Include paths are relative to the target root. `--public-include <dir>` also
exports an include directory to dependent targets; see
[public include directories](projects.md#public-include-directories).

## Inspect builds and configure editors

Print compile and link commands without running them:

```console
bspm build hello --dry-run
```

Print commands as the build runs, or show the discovered graph before building:

```console
bspm build hello -v
bspm build hello --explain
```

Inspect target dependencies, source units, module declarations, and imports
without compiling:

```console
bspm graph examples/nested-sources
bspm graph examples/project-config --project
```

Generate `compile_commands.json` for editor tooling:

```console
bspm compile-commands examples/nested-sources
bspm compile-commands examples/project-config --project
```

For a folder target, the database is written to that folder. For a configured
project, it is written to the project root and includes the selected targets
and their dependencies. Run `bspm compile-commands all` from the project root
to include every configured target. Regenerate it after changing sources,
target selection, or build options.

`graph`, `compile-commands`, and `build --dry-run` still plan package
dependencies when `bspm.deps` is present. They can fetch sources, populate
caches, and create a lockfile even though no compilation occurs.

## Run and clean

Build first, then run the produced executable:

```console
bspm build hello
bspm run hello
bspm run hello -v
```

`run` launches an existing executable; it does not rebuild sources. Libraries
are not runnable. Use the executable's path directly if you need to choose a
specific build profile or pass application arguments.

Remove generated build outputs:

```console
bspm clean hello
```

`clean` removes the target's entire `build/` directory, including all compiler
and mode profiles. Package caches under `.bspm/` are retained.

## Build outputs and incremental rebuilds

Each target keeps its generated files under its own build directory:

```text
hello/build/
├── gcc-debug/
├── gcc-release/
├── clang-debug/
└── msvc-debug/
```

Only profiles you build are created. GCC and Clang write dependency files
beside object files, so changes to included headers trigger recompilation of
affected sources.

GCC header units are cached under the profile's `gcm.cache/` directory. They
are reused while the compiler command remains unchanged. Changing compiler
flags or removing a generated `.gcm` artifact rebuilds the header unit and
its importer.
